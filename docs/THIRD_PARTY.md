# SIX current integration sources

Current firmware lives in `rhythmer/`. Root `firmware/six` is an earlier X0X-based prototype. Pins are recorded in `upstream-lock.json`.

- JIANT: https://github.com/juanjiant-bit/JIANT — current platform/HAL, dual-core scheduler, UI navigation, sequencer and DICE, scale/chord/ARP, song/section/arranger storage, ANALOG/FM6/PHASE/WHEEL/DRUM-X and FX. Original notices, LICENSING.md and LICENSES remain under rhythmer/. Local changes fix track roles, support four complete projects, adapt memory/voice budgets and add dedicated integration pages.
- X0X: https://github.com/charlesvestal/fm1-x0x — TB-3PO MIDI generator only. Its copied source and SPDX notices remain under rhythmer/firmware/six/. The X0X bass303 audio DSP, floating-point math and parameter layer were removed from the active product. acid_generate.c accepts only MIDI controls and the common SCL root/mask. No original multi-machine project or audio model is retained.
- Amenity: https://github.com/ejtb76/amenity — Jungle DSP, pattern/roll/one-shot/freeze/straight/auto-roll logic. Original notices are retained. Local adaptation reads packed PCM12 and takes timing from JIANT. The UI maps the same main knobs and physical performance keys into the JIANT workflow. The format/upload unit tests retain synthesized fixtures. The local emulator demonstration now uses the original Amenity Amen sample and a Think sample; these recordings are not covered by the firmware code license. See BREAK-SAMPLES.md for credits and exact preparation.
- Phaser: new four-stage allpass implementation in JIANT's former chorus bus; control coefficients are calculated per block and ramped per sample. Track DIST and the common master CLIP are JIANT implementations. This is not an extra chorus-plus-phaser bus.
- SDK boot files are obtained by the pinned upstream build procedure (AC79NN_SDK_V1.2.1_2023-12-13). SDK artifacts are not vendored into the source tree.

Rhythmer is an independent integration. References and retained notices identify the source projects; they do not imply endorsement.


Garden-FM is pinned to [3e6821b87a460e74b7b05545701f924bb9eb9359](https://github.com/nvhhh/Garden-FM/tree/3e6821b87a460e74b7b05545701f924bb9eb9359). Wavetable remains selectable. PHASE and LOFI are retired alongside WHEEL; their IDs remain reserved for project migration. Rhythmer draws its own note-reactive geometric views.

FMINI-1 uses the Felucca-derived synth port from Jazzy, and OberVave uses zvenson's [OberVave](https://github.com/zvenson/obervave) design and factory programs. The GPL notices are retained in `rhythmer/LICENSES/ported-fmini` and `rhythmer/LICENSES/ported-obervave`. Both engines keep their filter designs and use Rhythmer's sequencing, mixer and display.

[Elixir](https://github.com/dmajka/elixir) contributes the SEQ generator algorithms and the source settings used to design the LXR-X kits. LXR-X is a Drum-X reinterpretation, using the existing percussion voices and no copied LXR-02 waveform bank. See the source notices in `rhythmer/firmware/six/drum_generate.h` and `rhythmer/LICENSES/GPL-3.0-Elixir-LXR.txt`.

MONO2K integration is pinned to [ecb3b96c65d9fa92b258923df6317e5bb0ef6b4d](https://github.com/InigoHernandez/mono2k/tree/ecb3b96c65d9fa92b258923df6317e5bb0ef6b4d), by Iñigo Hernández, GPL-3.0-only. Selected FM+STAT, SWAV-SAW and SID-6581 machine kernels and their required tables are adapted in `rhythmer/firmware/src/eng_mono2k.c` and `rhythmer/firmware/mono2k/tables.h`; its license is retained alongside. These are MONO2K's clean-room designs, not Elektron ROM code. Rhythmer retains its own ADSR, sequencer, track filter, effects and dual-core scheduler. The 17 starting presets adapt MONO2K SYN settings to Rhythmer; they do not duplicate the full MONO2K chain or factory patch behavior. SID MSRC uses the previous track's stored sequence note at control rate, rather than sharing mutable voice state across cores. Engine IDs 18/19/20 are appended; favorites use retired rows 8/9/11, preserving row 15 settings metadata.

The MIDI-only TB-3PO adapter uses the shared SCL root and scale mask directly, including 8/12-degree scales. Its degree table exists only during a generation call. The common default is CHR; no private minor fallback, duplicate root/scale state or explicit-choice marker remains. The original unused six-scale API and table have been removed from the active product. Project structure and stored engine IDs remain stable.

Hortator MD percussion is pinned to [44c9ad4aa57bebf63f412bd552e57143c30b4065](https://github.com/DeadActive/hortator/tree/44c9ad4aa57bebf63f412bd552e57143c30b4065). All 21 MD synthesis models are adapted in `drum_md.c` / `md_*_kernels.h`; import procedure `tools/six/import_hortator_md.py`. Per-model oscillator scratch lives inside the state union, not in every ordinary drum lane. MD percussion shares the normal drum lane and voice management. Tune, decay and three named controls fit the existing 11-byte lane A/B schema; other original controls remain at factory settings. This does not import Hortator's entire firmware, banks, UI or sample pack. Copyright DEADACTIVE and original upstream notices remain. Mutable Instruments math is accompanied by its MIT notice.
